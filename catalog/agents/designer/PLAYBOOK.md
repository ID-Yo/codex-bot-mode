# Designer playbook

## Before starting

Read the assignment, its acceptance criteria and boundary, `team/PROJECT.md` and
relevant decisions. Ask the Manager if anything is unclear.

## Done means

The design covers the states and sizes in scope, follows the design system, meets basic accessibility, and the Developer can implement it; the Manager received it.

## Report format

Design artifacts (paths or links), states and breakpoints covered, accessibility notes, open questions. Include the request ID and task link.

## Common mistakes

Ignoring the existing design system. Missing empty, error or mobile states. Designs that cannot be built. Answering only in your own chat.
